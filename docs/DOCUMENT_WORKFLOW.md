# Договоры и приёмка в портале

Портал использует один основной договор и две короткие дополнительные записи. Клиент принимает точную PDF-версию от имени своей компании, а портал сохраняет доказательства решения.

## Документы

| Документ | Когда нужен |
| --- | --- |
| Project Services Agreement | Обязательно до начала платной работы: стороны, объём, цена, оплата, права, ответственность и срок |
| Project Change Order | Только когда после принятия договора меняются объём, цена или срок |
| Delivery Acceptance Record | После передачи результата и проверки клиентом |
| Invoice | Отдельный запрос оплаты, связанный с принятым договором |

Старые документы остаются в истории и не переписываются. Для нового заказа создаётся новый Project Services Agreement.

## Что подготовить до отправки

1. В **Provider settings** заполнить настоящее имя, contracting status / legal capacity, registration or tax ID, адрес, страну и email. Банковские реквизиты должны соответствовать счёту, способному принимать деловые переводы.
2. Форму W-8BEN не загружать в портал. Хранить актуальную форму отдельно и отправлять американскому заказчику напрямую, если он её запросит.
3. У клиента указать юридическое название бизнеса, штат / страну регистрации или ведения бизнеса, деловой адрес, имя и должность представителя. Представитель должен иметь право принять договор от имени компании.
4. В проекте проверить описание, scope, exclusions, цену, валюту и ожидаемую дату.

## Порядок реального заказа

1. Открыть **Agreements & records → New agreement / record**.
2. Выбрать **Project Services Agreement**, клиента и проект.
3. Заполнить все поля. Особое внимание: deliverables, exclusions, обязанности клиента, payment schedule, acceptance criteria, cancellation, данные и доступы.
4. Сохранить draft, скачать PDF и прочитать его целиком. Если реквизиты изменились, создать новую версию — старый snapshot не обновляется автоматически.
5. Нажать **Send to client**. Клиент скачивает PDF, отмечает полномочия и выбирает **Accept agreement** либо **Request changes**.
6. После принятия можно выставить advance invoice и начинать работу согласно payment schedule.
7. При изменении условий создать **Project Change Order**, привязать его к принятому договору и указать новый полный итог проекта.
8. После передачи результата создать **Delivery Acceptance Record**. Клиент выбирает **Accept delivery**, принимает с заранее записанными minor items или запрашивает изменения.
9. Final invoice требует принятого Delivery Acceptance Record.

## Доказательства принятия

Для каждого решения сохраняются:

- номер документа, точная версия и SHA-256 замороженного PDF;
- текст подтверждения полномочий и согласия;
- юридическое имя и юрисдикция клиента;
- имя, email и должность представителя;
- аккаунт, решение, комментарий, дата, время, IP-адрес и user agent.

Просмотр, молчание или оплата сами по себе не считаются принятием. Новая версия не изменяет ранее отправленный PDF и доказательства по нему.

## Практические границы

Шаблон рассчитан на обычные B2B-проекты: веб-приложения, Telegram-боты, автоматизацию и разработку ПО. Для регулируемых данных, найма сотрудников, долей в компании, крупных enterprise-заказов или условий, навязанных закупочным отделом клиента, используется отдельный документ. Американская компания также может попросить подписать её собственный vendor agreement или NDA.

PDF всегда белый с чёрным текстом и линиями, независимо от тёмной темы портала.

## Обновление и проверка

После `git pull`:

```bash
docker compose exec app composer install --no-interaction --prefer-dist
docker compose exec app npm install --ignore-scripts
docker compose exec app php artisan migrate --force
docker compose exec app npm run build
docker compose restart queue scheduler
```

Не использовать `migrate:fresh` на рабочей базе. Перед обновлением сделать backup MySQL и `storage/app`.

Проверки разработчика:

```bash
docker compose exec app php artisan test
docker compose exec app ./vendor/bin/pint --test
docker compose exec app composer validate --no-check-publish
docker compose exec app npm run build
```
